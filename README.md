Yandex & Google panorama downloader
===================================

## Офлайн-просмотрщик Python + GTK4

Запуск из каталога проекта на этой машине (не требует сервера или интернета):

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox
```

Без аргумента открывается первая найденная панорама; остальные доступны в списке
в заголовке окна. Сканируется каталог `map` рядом со скриптом, независимо от
текущего рабочего каталога. Можно задать другой через `--library /путь/к/map`.
Кнопка «Открыть…» позволяет выбрать `metadata.json` из другого архива.

Структура локального архива:

```text
map/<imageId>/metadata.json
map/<imageId>/0/tile_0_0.jpg
map/<imageId>/0/tile_0_1.jpg
...
```

Поддерживаются JSON-манифест из локального сервера и исходный JSON-ответ Яндекса.
Нужны исходные тайлы: склеенный JPEG с текстовой подписью не используется.
Монитор загрузки автоматически экспортирует метаданные из БД рядом с тайлами,
включая уже скачанные панорамы без `metadata.json`. Для ручной загрузки тайлов
экспорт выполните отдельно перед отключением БД. В процессе просмотра программа
не обращается ни к БД, ни к сети.

Управление:

- левая кнопка мыши + перетаскивание — поворот;
- колесо мыши, `+` / `−` — масштабирование;
- стрелки — поворот с клавиатуры;
- `Home` — начальное направление и угол обзора;
- `F11` — полный экран, `Esc` — выход из него;
- `Ctrl+O` — открыть метаданные;
- `Ctrl+S` или кнопка камеры — сохранить текущий вид в PNG.

Проекция учитывает `EquirectangularProjection.Origin`, точные размеры изображения
и неполный вертикальный обзор. Отсутствующие или повреждённые тайлы показываются
серой сеткой; область за пределами снятого изображения — тёмным фоном.
Автоматически выбирается самый подробный полностью скачанный уровень, а если
полных уровней нет — самый подробный из доступных. `--level 0` выбирает уровень явно.

Текстура хранится страницами в OpenGL texture array: ширина панорамы может
превышать `GL_MAX_TEXTURE_SIZE`. По умолчанию используется бюджет до 768 MiB
для текстуры (расчёт с запасом 4 байта на пиксель; прочие расходы GPU не включены).
При превышении бюджета или лимита слоёв текстура уменьшается в 2, 4, … раз;
активный масштаб указан внизу окна. Исходные файлы не меняются.
На видеокарте с небольшим объёмом памяти:

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox --gpu-memory 128
```

### Зависимости просмотрщика

Нужны Python, GTK4, PyGObject, PyOpenGL, Pillow, NumPy и OpenGL 3.3.
Все Python-зависимости перечислены в `requirements.txt`. Запускайте программу
из виртуального окружения после установки зависимостей.

Для Arch Linux:

```bash
sudo pacman -S --needed gtk4 python-gobject python-opengl python-pillow python-numpy
```

Для Debian/Ubuntu:

```bash
sudo apt install python3-gi gir1.2-gtk-4.0 python3-opengl python3-pil python3-numpy
```

Установка PyGObject через pip требует системных библиотек GTK4,
GObject Introspection и инструментов сборки. `requirements-viewer.txt`
содержит сокращённый список только для просмотрщика.

### Снимок без графического интерфейса

CPU-рендер использует Pillow и NumPy, читает только нужные тайлы в исходном
разрешении и работает без GTK, OpenGL, DISPLAY и сети:

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox \
  --render /tmp/panorama-view.png --width 1135 --height 1033 \
  --yaw 60.583633 --pitch -7.411967 --fov 60
```

`yaw` — азимут от севера по часовой стрелке, `pitch` — наклон вверх от горизонта,
`fov` — вертикальный угол обзора. Значения задаются в градусах. Эти параметры
работают и при обычном запуске окна.

### Дата и время съёмки

Под панорамой отображается дата съёмки и источник. `capturedAt` **не является
датой съёмки**: расширение добавляет его по своим часам при перехвате ответа.
`receivedAt` означает время приёма на сервере, также не время съёмки.

Из `Data.timestamp` берётся только дата: у проверенных соседних панорам API
возвращает одинаковое 12:00 UTC, хотя суффиксы `panoramaId` меняются с шагом
в несколько секунд. Время из ID показывается с пометкой **«предположительно,
из ID»** и явным UTC. Формат ID не подтверждён документацией провайдера.
При расхождении дат больше суток выводится предупреждение; если известен
лишь год/месяц, день и точное время не выдумываются. Разница в один день допускается
из-за неизвестного часового пояса даты провайдера и не подтверждает время из ID.

Для старых локальных манифестов дата определяется непосредственно из исходного
ответа; повторный экспорт и подключение к БД для просмотра не нужны.
Слой Солнца и Луны по-прежнему использует **текущее время**, не предположительное время съёмки.

### Солнце, Луна и горизонт

В меню **«Небо»** можно независимо включить Солнце и Луну. По умолчанию оба
выключены. Если включено хотя бы одно светило, появляется тонкая голубая линия
астрономического горизонта (высота 0°). Светила отображаются и ниже горизонта,
включая неснятую часть панорамы. Это наложение поверх фотографии: здания,
деревья и земля его не закрывают.

Расчёт использует координаты `Point.coordinates` открытой панорамы и текущее
системное время в UTC, а не дату съёмки. Положение пересчитывается раз в минуту,
при включении слоя и смене панорамы; поворот и масштаб камеры сразу меняют
проекцию дисков на экран. В меню показаны момент расчёта, азимут, высота,
угловой диаметр и освещённая доля Луны. При отсутствии координат отображается
причина недоступности, старое наложение сбрасывается.

Размер дисков определяется физическим радиусом и текущим расстоянием до наблюдателя.
Минимального размера в пикселях нет: при широком обзоре они действительно маленькие.
Вокруг включённых светил показаны красные окружности для поиска: их радиус
не меньше 24 пикселей, с отступом от диска. Это указатели, а не физический размер светил.
Лунная фаза и ориентация освещённой части рассчитываются по направлению на Солнце.
Атмосферная рефракция, рельеф, текстура поверхности и затмения не моделируются;
высота места над уровнем моря принята равной 0 м. Точность привязки к фотографии
также зависит от ориентации исходной панорамы.

Новая зависимость `ephem` включена в `requirements.txt` и `requirements-viewer.txt`:

```bash
.venv/bin/python -m pip install -r requirements.txt
```

При просмотре сеть не используется, скачивать эфемериды не требуется.
Снимок текущего окна через Ctrl+S включает наложение. CPU-экспорт `--render`
и печатная развёртка `--globe` остаются без него.
Расчёты и независимые эталоны описаны в [docs/sky.md](docs/sky.md).

### Развёртка для наклейки на шар

Кнопка **«На шар…»** открывает настройки печатной развёртки: диаметр шара,
число лепестков, DPI и азимут центра первого лепестка. PDF генерируется
в фоне. По умолчанию: **100 мм, 24 лепестка, 300 DPI**, два листа A4.
Дополнительная Python-зависимость `reportlab` включена в оба requirements-файла.

Экспорт без GTK, OpenGL и подключения к сети:

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox \
  --globe panorama-globe-100mm.pdf \
  --globe-diameter 100 --globe-gores 24 --globe-dpi 300 --yaw 0
```

Поддерживаются диаметры 20–150 мм, 12–48 лепестков и 72–600 DPI. Ориентация
A4 выбирается автоматически; каждый лепесток целиком помещается на странице.
`--yaw` задаёт центр первого лепестка (по умолчанию север); в окне начальное
значение берётся из текущего направления камеры. Наклон камеры и угол обзора
не меняют развёртку: экспортируется вся доступная панорама выбранного уровня.

Порядок сборки:

1. Измерьте напечатанный на 3D-принтере шар и укажите его фактический диаметр.
2. Печатайте PDF с настройкой **«Фактический размер / 100%»**, без подгонки
   к листу. Измерьте контрольный отрезок: он должен быть ровно 50 мм.
3. Сначала вырежьте и примерьте один лепесток. Для шара 100 мм его длина
   от полюса до полюса — 157,08 мм, ширина на экваторе при 24 лепестках — 13,09 мм.
4. Вырезайте по контуру. Номера, азимуты и отметки экватора находятся снаружи;
   перед вырезанием перенесите нужные отметки на обратную сторону.
5. Клейте лепестки встык в порядке 01, 02, …, 24, затем замкните 24 с 01.
   Верх листа соответствует зениту, низ — надиру; экватор проходит через середину.
   Клапанов и припусков на нахлёст нет. Примеряйте и разглаживайте от экватора к полюсам.

Это синусоидальные лепестки: `x = R · cos(φ) · (λ − λ₀)`,
`y = R · φ`, где `R` — радиус в мм, `φ` — широта, `λ₀` — центральный
меридиан лепестка. Масштаб вдоль центрального меридиана и параллелей сохраняется;
соседние края берут одинаковые долготы исходной панорамы, включая шов 360°.
Размеры в PDF задаются в физических единицах и не зависят от округления пикселей.

Плоская бумага не покрывает сферу без деформации: возможны небольшие складки,
особенно у полюсов. Больше узких лепестков и тонкая бумага облегчают подгонку.
Серая область означает отсутствующий вертикальный обзор, клетчатая — отсутствующие
или повреждённые тайлы. Программа не дорисовывает землю и небо. Получится изображение
на внешней поверхности шара; перспектива будет отличаться от просмотра из центра
виртуальной панорамы. Физическую сборку следует проверить пробной печатью.

Первая версия показывает отдельные панорамы и переключает их через список;
стрелки переходов, подписи объектов и исторические снимки поверх изображения
пока не отображаются. Их исходные данные остаются в манифесте.

Математика и проверка соответствия Яндексу: [docs/projection.md](docs/projection.md).

Проект содержит:

1. Расширение для браузера `pano-monitoring-google`
2. Расширение для браузера `pano-monitoring-yandex`
3. Flask сервер `monitoring-server`
4. Скрипт для скачивания и склейки панорам [download_in_realtime.py](download_in_realtime.py)

## Установка и запуск

Для существующей установки с V001/V002 перед запуском обновлённого сервера
и монитора требуется **V003, V004 и заполнение каталога**. Команды и описание таблиц:
[docs/catalog.md](docs/catalog.md). Просмотрщик новых таблиц не требует.

Для установки необходимо:

1. Подготовить базу данных PostgreSQL (скрипт [V001__Initial_schema.sql](db/migrations/V001__Initial_schema.sql))
2. Активировать виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

3. Запустить сервер [monitoring-server](monitoring-server), должен быть запущен
   на http://127.0.0.1:5000.
4. Установить расширение в браузер (в Firefox: about:debugging -> This Firefox
   -> Load temporary addon)

## Как это работает?

Расширение для браузера перехватывает запросы от Yandex или Google, извлекает
данные о текущей панораме из содержимого страницы и сохраняет их в базе данных
пользователя (HTTP endpoint http://127.0.0.1:5000/aa/yandex-panorama или 
http://127.0.0.1:5000/aa/google-panorama).

Запущенный скрипт `download_in_real_time.py` ищет в таблице `aa.panorama`
записи для панорам, которые не были скачаны и скачивает их потайлово, после
этого запускает скрипт `merge.py` для склейки панорамы. Итоговые изображения
сохраняются в директорию `panos`.

Загрузчики Яндекса и Google выполняют запросы последовательно с паузой
**0,5 секунды после ответа** перед следующим запросом. Для ручного запуска
паузу можно увеличить: `.venv/bin/python pano.py IMAGE_ID 0 --request-interval 2`.
Существующие тайлы пропускаются без HTTP-запросов.

При HTTP 429 повторяется тот же тайл после пауз 30, 60, 120, 240, 480,
затем 600 секунд. Если `Retry-After` (секунды или HTTP-дата) требует более долгого
ожидания, используется оно без ограничения в 600 секунд. После успешного запроса
счётчик повторов сбрасывается. Загрузчик остаётся запущенным во время ожидания,
поэтому монитор не перезапускает его каждые 10 секунд и не запускает склейку.
Ожидание и адрес тайла выводятся в консоль; остановить загрузку можно через Ctrl+C.
Повторные 429 обрабатываются до успеха или ручной остановки. Ограничитель действует
в пределах одного процесса: несколько загрузчиков не координируют свои запросы.

В принципе, для скачивания и склейки панорам достаточно скриптов `pano.py` (`pano-google.py`)
и `merge.py`, но для этого нужно знать ID панорамы. Также скрипт `merge.py`
добавляет на панораму информацию о координатах, месте, даты и времени съёмки -
эта информация извлекается соотвутствующим плагином для браузера.

## Метаданные для офлайн-просмотрщика (Firefox, версия 1.1)

Расширение `pano-monitoring-yandex` дополнительно перехватывает **ответы**
`https://api-maps.yandex.ru/services/panoramas/*` через Firefox
`webRequest.filterResponseData`. Оригинальные байты сразу передаются странице
без изменений. Дополнительные запросы к Яндексу расширение не делает.

Сохраняются полный исходный JSON-ответ, включая неизвестные поля, и удобные
поля манифеста:

- `imageId` — идентификатор изображения в URL тайлов и каталоге `map`;
- `panoramaId` — отдельный длинный идентификатор панорамы Яндекса;
- `projection` — исходный `EquirectangularProjection`, включая `Origin`;
- `images` — исходный `Images`: точные ширина/высота каждого уровня,
  номера уровней и размер тайлов;
- `position`, `timestamp`, `defaultView` — положение, исходная временная метка провайдера и начальный вид;
- `tileUrlTemplate`, `localTileTemplate` — адреса тайлов и локальные пути;
- `rawResponse.data.Annotation` — переходы, граф соседей, подписи, организации
  и исторические панорамы; другие поля ответа тоже остаются в `rawResponse`;
- `capturedAt` / `observedAt` — время перехвата по часам браузера, не съёмки;
- `receivedAt` — время приёма сервером;
- `sourceUrl`, `schemaVersion` — происхождение и версия формата.

`Origin` сохраняется без пересчёта: его соглашения нужно учитывать при реализации
просмотрщика, а не подменять предполагаемым `angularBBox`. Флаг
`geometryFieldsPresent` означает наличие основных полей, **не** проверку
корректности рендеринга. При изменении схемы ответ всё равно сохраняется,
а `missingFields` указывает отсутствующие основные поля.

Для реального примера `Z7lngTdIrFox` максимальный уровень имеет размер
18944 × 7271 при тайлах 256 × 256. Последнюю строку нельзя растягивать до
полных 256 пикселей или считать высотой панорамы 29 × 256. Для будущего
просмотрщика используйте оригинальные тайлы и размеры из манифеста.
`merge.py` создаёт плоскую картинку с подписью; для просмотра используйте архив тайлов.

### Обновление

1. Примените новую миграцию к существующей БД **от администратора PostgreSQL**
   или владельца схемы `aa` (V001 повторно запускать не нужно).
   У прикладного пользователя `allarchive` может не быть права `CREATE` в схеме:

   ```bash
   sudo -u postgres psql -d panoramas -v ON_ERROR_STOP=1 --single-transaction \
     < db/migrations/V002__Yandex_panorama_metadata.sql
   ```

2. Перезапустите Flask-сервер с обновлённым кодом. Модуль
   `monitoring-server/panorama_metadata.py` должен находиться рядом с сервером.
3. В Firefox откройте `about:debugging#/runtime/this-firefox` и перезагрузите
   расширение (или загрузите `pano-monitoring-yandex/manifest.json`). Добавлены
   разрешения на API метаданных, хранилище и таймер повторной отправки.
4. Перезагрузите страницу Яндекс Карт и откройте панораму. Уже прошедшие до
   загрузки расширения ответы задним числом получить нельзя.

Ответы отправляются на `POST /aa/yandex-panorama-metadata`. Сервер сохраняет
последний ответ для каждого `imageId` в `aa.yandex_panorama_metadata` (JSONB).
Повторная отправка того же исходного ответа не создаёт дополнительную запись журнала.
`capturedAt` больше не используется для определения свежести: часы клиента могут
ошибаться. Каталог отражает последний принятый ответ, а отличающиеся исходные
ответы сохраняются в `aa.panorama_capture`. Это порядок получения, не гарантия
свежести данных провайдера. Изменённый ответ также добавляет запись
в `panorama_log`, чтобы существующий загрузчик обнаружил изображение.
Координаты этой записи берутся из ответа, независимо от состояния вкладки.

Если сервер недоступен, расширение хранит последнюю полученную версию для
каждого изображения в `browser.storage.local` и повторяет отправку раз в минуту
и при запуске фонового скрипта. После подтверждения сервера запись удаляется
из очереди. Не удаляйте расширение/его данные до отправки очереди; для временного
расширения также не следует полагаться на сохранение данных при его удалении
Firefox. `unlimitedStorage` снимает обычную квоту очереди, но не ограничения диска.
Ошибка записи в хранилище отображается в консоли расширения.
Ответы больше 16 MiB пропускаются с сообщением в консоли, а не обрезаются.

Старый журнал запросов тайлов сохраняется. Теперь в его `panorama_log_meta`
есть также `observed_view.direction` и `observed_view.span` из URL. Это снимок
состояния интерфейса в момент запроса тайла, а не надёжная геометрия изображения
и не непрерывная запись положения камеры. Основной источник для просмотрщика —
таблица `yandex_panorama_metadata`.

### Проверка и экспорт без обращения к Яндексу

Просмотрщик включает в список только каталоги с `metadata.json`: одних тайлов
недостаточно для определения точной проекции. `download_in_real_time.py` сохраняет
метаданные перед скачиванием новой панорамы Яндекса и дополняет старые архивы
при каждой проверке очереди, даже если склеенный JPEG уже существует.
Существующие `metadata.json` не перезаписываются.

Разовый экспорт недостающих файлов из локальной PostgreSQL для всех каталогов `map`:

```bash
.venv/bin/python -m panorama_archive.metadata
```

Можно указать другой каталог через `--root /путь/к/map`. Перезапустите просмотрщик,
чтобы обновить список. Если ответа с геометрией нет в БД, файл не создаётся:
такую панораму нужно открыть в Firefox с включённым расширением захвата метаданных.
Этот экспорт предназначен для панорам Яндекса.

После открытия панорамы её манифест доступен через локальный сервер:

```bash
curl --fail http://127.0.0.1:5000/aa/yandex-panorama-metadata/Z7lngTdIrFox \
  -o map/Z7lngTdIrFox/metadata.json
```

Каталог для файла должен существовать. Экспорт содержит все исходные метаданные,
но не сами изображения. Соседние/исторические панорамы перечислены как ссылки;
их тайлы и полные метаданные не скачиваются автоматически. Для старых архивов
нужно повторно открыть соответствующие панорамы с обновлённым расширением.

### Тесты

Проверяются геометрия проекции, чтение тайлов, неполные архивы, CPU-рендер и CLI,
управление камерой, загрузка и отмена страниц атласа, работа с GPU через подмену
OpenGL, скачивание, склейка и обработка ошибок. Архитектурные тесты проверяют
shebang, размещение функций в классах, длину методов до 10 строк и зависимости.

```bash
node tests/metadata.test.js
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

Для отдельной проверки реального GTK/OpenGL нужны графическая сессия и локальный
архив. Команда проверяет управление, сохраняет снимок и закрывает окно:

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox --smoke-test /tmp/panorama-smoke.png
```

Код просмотрщика разделён на модель архива, чтение тайлов, геометрию проекции,
камеру, фоновую загрузку, OpenGL и GTK-интерфейс в `panorama_viewer`.
`panorama_archive` содержит загрузчик и склейку; сервер отделяет нормализацию
метаданных от SQL в `panorama_metadata.py` и `repository.py`. Корневые скрипты
сохраняют прежние точки входа.

Фикстура `tests/fixtures/yandex-panorama.json` — публичный ответ для точки
132.199871,43.357577, полученный 2026-09-23. Тесты проверяют сохранность данных,
передачу потока, сбой сервера, восстановление очереди и гонку ответов.
Firefox API и соединение PostgreSQL в этих тестах подменяются; запуск расширения
в настоящем Firefox и применение миграции проверяются отдельно.

В блоке «Небо и время» на левой панели можно выбрать дату расчёта в диалоге с календарём и задать время UTC
вручную (`ЧЧ:ММ` или `ЧЧ:ММ:СС`) либо ползунком на панели. Солнце и Луна пересчитываются при корректном вводе.
При открытии панорамы время берётся из метаданных: время из ID считается
предположительным; если известна только дата, используется условное 12:00 UTC.
Если полной даты нет, выбирается текущее время с соответствующей пометкой.
Кнопка «Из метаданных» восстанавливает исходное значение, «Сейчас» включает
текущее время с обновлением раз в минуту.

### Скачивание через SOCKS-прокси

Положите `proxies.txt` в текущий рабочий каталог, откуда запускается
`download_in_real_time.py`, `pano.py` или `pano-google.py`. Один прокси на строку:

```text
# Примеры, замените своими адресами
socks5h://127.0.0.1:1080
socks5h://username:password@127.0.0.1:1081
```

Без схемы используется `socks5h://`; при такой схеме DNS разрешает прокси.
Спецсимволы в логине и пароле необходимо URL-кодировать. Пустые строки и строки
комментариев пропускаются, одинаковые записи не создают дополнительные потоки.
Файл `proxies.txt` исключён из Git. Адреса и пароли не выводятся в сообщения об ошибках.

Каждый уникальный прокси получает один поток и отдельную HTTP-сессию.
Столбцы тайлов распределяются между потоками; существующие файлы пропускаются.
Пауза `--request-interval` (по умолчанию 0,5 с) и ожидание при HTTP 429 действуют
отдельно для каждого прокси. Поток при 429 ждёт и повторяет запрос через тот же
прокси. При сетевой ошибке загрузка останавливается с сохранением готовых тайлов;
следующий запуск продолжит её. Перехода на прямое соединение при ошибке нет.

Если `proxies.txt` отсутствует или пуст, используется прежняя последовательная
загрузка. Другой файл можно задать для скачивания вручную:

```bash
.venv/bin/python pano.py IMAGE_ID 0 --proxies-file /path/to/proxies.txt
```

Для SOCKS требуется зависимость `requests[socks]` из `requirements.txt`.

При запуске GTK-просмотрщик в фоне запрашивает каталог PostgreSQL и сохраняет
недостающие `metadata.json` для панорам, чьи тайлы уже есть в `--library`.
Список обновляется автоматически, текущая панорама сохраняется. В существующих
манифестах обновляется только адрес `catalogTitle`; исходный ответ API и геометрия
сохраняются. При недоступности БД просмотрщик
продолжает работать по локальным файлам; подключение и SQL-запрос ограничены
таймаутами по 3 секунды. Панорамы без скачанных тайлов не добавляются из БД.

Сведения о съёмке, загрузке и направлении просмотра находятся в левой панели
GTK4. Кнопка панели в верхней части окна скрывает и показывает её; при скрытии
освободившееся место занимает панорама.

Кнопки открытия, выбора панорамы, сброса вида, полного экрана и экспорта
расположены в левой панели. Дата, время и переключатели Солнца и Луны
постоянно раскрыты в блоке «Небо и время». В заголовке окна оставлена
кнопка скрытия и восстановления панели.

Дата и время отображаются и редактируются в общем блоке. Исходные сведения
о съёмке доступны в подсказке заголовка «Дата и время · UTC». Расчётные
координаты светил и освещённость Луны показаны в подсказке «Расчётные данные».

Действия «Сброс», «Экран», «Снимок», «На шар» расположены сверху панели
компактными кнопками с иконками. В блоке даты и времени можно выбрать фиксированное
смещение от UTC (−12:00…+14:00 с шагом 15 минут). Календарь, ручной ввод и ползунок
используют выбранный пояс. Смена пояса сохраняет момент расчёта, меняя только
отображение; автоматический переход на летнее время не применяется.

Адрес каталога сохраняется в `metadata.json` отдельным полем `catalogTitle`
и используется просмотрщиком, даже если `Point.name` в исходном API пуст.
Пустые ответы API не стирают адрес из наблюдений плагина. При обновлении
библиотеки адрес актуализируется и для уже открытой панорамы. Готовые JPEG
нужно пересоздать командой `merge.py`, чтобы обновить подпись.

### Маркеры панорамы

Переключатель «Маркеры» в левой панели показывает номера домов и другие подписи
из сохранённых `Annotation.Markers`. Позиции вычисляются по координатам маркера
и камеры, с учётом разницы высот. Маркеры за камерой, за краем экрана и
перекрывающиеся подписи скрываются; при совпадении предпочтение ближним.
Полное описание доступно при наведении. Подписи не мешают вращению мышью
и включаются в экспорт «Снимок», если переключатель включён.

Функция работает без сети и не загружает внешние стили маркеров. Без карты
глубины подписи могут быть видны сквозь здания. Экспорт развёртки на шар
и отдельный CPU-рендер используют исходное изображение без этих подписей.

### Переходы между панорамами

Переключатель «Переходы» показывает стрелки соседних панорам из сохранённых
`Graph`, `Thoroughfares` и `Connections`. Синяя стрелка открывает локально
скачанную панораму, сохраняя азимут, наклон и угол обзора. Серые стрелки
обозначают недоступные панорамы; загрузка из интернета по клику не выполняется.
Направления переходов отображаются на 12° ниже горизонта, чтобы отделить
навигацию от подписей домов. Навигационные кнопки не включаются в снимок.

### Другие даты съёмки

Блок «Другие даты» показывает годы из `Annotation.HistoricalPanoramas`.
Скачанные версии открываются кнопкой года; недоступные локально неактивны,
текущая версия выделена. Азимут, наклон и масштаб сохраняются, а время
расчёта светил обновляется из метаданных выбранной версии. Используются
только прямые связи по ID, без поиска похожих точек по координатам.

### Диагностика прокси

```bash
.venv/bin/python check_proxies.py
.venv/bin/python check_proxies.py --file proxies.txt --timeout 10 --workers 4
.venv/bin/python check_proxies.py --only-failed
```

Скрипт проверяет в том числе прокси в строках с `#`, не изменяя файл:
TCP-порт, согласование SOCKS5 и авторизацию, затем HTTP-запросы к `yandex.ru`,
`google.com`, `mail.ru`, `wayfarer-crm.com`. HTTP-редиректы выводятся как ответы
и не выполняются: проверка не переключается на HTTPS. Ошибки HTTP 4xx/5xx
показываются отдельно от ошибок соединения. Ответ может быть сформирован
как целевым сервером, так и прокси. Если порт или SOCKS недоступен, последующие
этапы помечаются как непроверенные. Пароли в отчёте не отображаются.

По умолчанию таймаут операции 5 секунд, одновременно проверяются до 4 прокси.
Опция `--only-failed` скрывает отчёты об исправных прокси; для проблемных
показываются все этапы проверки. Ошибки чтения и разбора файла остаются видны.
Код завершения 0 означает успешные проверки, 1 — ошибки или отсутствие прокси.
Для SOCKS4 нет отдельной проверки пароля; доступ проверяется HTTP-запросами.
Если SOCKS5 выбрал работу без авторизации, скрипт явно сообщает, что пароль
сервером не проверялся.
