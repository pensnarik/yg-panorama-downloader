Yandex & Google panorama downloader
===================================

## Офлайн-просмотрщик Python + GTK4

Запуск из каталога проекта на этой машине (не требует сервера или интернета):

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox
```

Без аргумента открывается первая найденная панорама; остальные доступны в списке
в заголовке окна. Сканируется каталог `map` рядом со скриптом, независимо от
текущего рабочего каталога. Можно задать другой через `--library /путь/к/map`.
Кнопка «Открыть…» позволяет выбрать `metadata.json` из другого архива.

Структура локального архива:

```text
map/<imageId>/metadata.json
map/<imageId>/0/tile_0_0.jpg
map/<imageId>/0/tile_0_1.jpg
...
```

Поддерживаются JSON-манифест из локального сервера и исходный JSON-ответ Яндекса.
Нужны исходные тайлы: склеенный JPEG с текстовой подписью не используется.
Экспорт метаданных из БД через локальный сервер описан ниже. Для новых панорам
его нужно выполнить один раз, прежде чем отключать сервер; в процессе просмотра
программа не обращается ни к БД, ни к сети.

Управление:

- левая кнопка мыши + перетаскивание — поворот;
- колесо мыши, `+` / `−` — масштабирование;
- стрелки — поворот с клавиатуры;
- `Home` — начальное направление и угол обзора;
- `F11` — полный экран, `Esc` — выход из него;
- `Ctrl+O` — открыть метаданные;
- `Ctrl+S` или кнопка камеры — сохранить текущий вид в PNG.

Проекция учитывает `EquirectangularProjection.Origin`, точные размеры изображения
и неполный вертикальный обзор. Отсутствующие или повреждённые тайлы показываются
серой сеткой; область за пределами снятого изображения — тёмным фоном.
Автоматически выбирается самый подробный полностью скачанный уровень, а если
полных уровней нет — самый подробный из доступных. `--level 0` выбирает уровень явно.

Текстура хранится страницами в OpenGL texture array: ширина панорамы может
превышать `GL_MAX_TEXTURE_SIZE`. По умолчанию используется бюджет до 768 MiB
для текстуры (расчёт с запасом 4 байта на пиксель; прочие расходы GPU не включены).
При превышении бюджета или лимита слоёв текстура уменьшается в 2, 4, … раз;
активный масштаб указан внизу окна. Исходные файлы не меняются.
На видеокарте с небольшим объёмом памяти:

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox --gpu-memory 128
```

### Зависимости просмотрщика

Нужны Python, GTK4, PyGObject, PyOpenGL, Pillow, NumPy и OpenGL 3.3.
Все Python-зависимости перечислены в `requirements.txt`. Запускайте программу
из виртуального окружения после установки зависимостей.

Для Arch Linux:

```bash
sudo pacman -S --needed gtk4 python-gobject python-opengl python-pillow python-numpy
```

Для Debian/Ubuntu:

```bash
sudo apt install python3-gi gir1.2-gtk-4.0 python3-opengl python3-pil python3-numpy
```

Установка PyGObject через pip требует системных библиотек GTK4,
GObject Introspection и инструментов сборки. `requirements-viewer.txt`
содержит сокращённый список только для просмотрщика.

### Снимок без графического интерфейса

CPU-рендер использует Pillow и NumPy, читает только нужные тайлы в исходном
разрешении и работает без GTK, OpenGL, DISPLAY и сети:

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox \
  --render /tmp/panorama-view.png --width 1135 --height 1033 \
  --yaw 60.583633 --pitch -7.411967 --fov 60
```

`yaw` — азимут от севера по часовой стрелке, `pitch` — наклон вверх от горизонта,
`fov` — вертикальный угол обзора. Значения задаются в градусах. Эти параметры
работают и при обычном запуске окна.

Первая версия показывает отдельные панорамы и переключает их через список;
стрелки переходов, подписи объектов и исторические снимки поверх изображения
пока не отображаются. Их исходные данные остаются в манифесте.

Математика и проверка соответствия Яндексу: [docs/projection.md](docs/projection.md).

Проект содержит:

1. Расширение для браузера `pano-monitoring-google`
2. Расширение для браузера `pano-monitoring-yandex`
3. Flask сервер `monitoring-server`
4. Скрипт для скачивания и склейки панорам [download_in_realtime.py](download_in_realtime.py)

## Установка и запуск

Для установки необходимо:

1. Подготовить базу данных PostgreSQL (скрипт [V001__Initial_schema.sql](db/migrations/V001__Initial_schema.sql))
2. Активировать виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

3. Запустить сервер [monitoring-server](monitoring-server), должен быть запущен
   на http://127.0.0.1:5000.
4. Установить расширение в браузер (в Firefox: about:debugging -> This Firefox
   -> Load temporary addon)

## Как это работает?

Расширение для браузера перехватывает запросы от Yandex или Google, извлекает
данные о текущей панораме из содержимого страницы и сохраняет их в базе данных
пользователя (HTTP endpoint http://127.0.0.1:5000/aa/yandex-panorama или 
http://127.0.0.1:5000/aa/google-panorama).

Запущенный скрипт `download_in_real_time.py` ищет в таблице `panorama_log`
записи для панорам, которые не были скачаны и скачивает их потайлово, после
этого запускает скрипт `merge.py` для склейки панорамы. Итоговые изображения
сохраняются в директорию `panos`.

В принципе, для скачивания и склейки панорам достаточно скриптов `pano.py` (`pano-google.py`)
и `merge.py`, но для этого нужно знать ID панорамы. Также скрипт `merge.py`
добавляет на панораму информацию о координатах, месте, даты и времени съёмки -
эта информация извлекается соотвутствующим плагином для браузера.

## Метаданные для офлайн-просмотрщика (Firefox, версия 1.1)

Расширение `pano-monitoring-yandex` дополнительно перехватывает **ответы**
`https://api-maps.yandex.ru/services/panoramas/*` через Firefox
`webRequest.filterResponseData`. Оригинальные байты сразу передаются странице
без изменений. Дополнительные запросы к Яндексу расширение не делает.

Сохраняются полный исходный JSON-ответ, включая неизвестные поля, и удобные
поля манифеста:

- `imageId` — идентификатор изображения в URL тайлов и каталоге `map`;
- `panoramaId` — отдельный длинный идентификатор панорамы Яндекса;
- `projection` — исходный `EquirectangularProjection`, включая `Origin`;
- `images` — исходный `Images`: точные ширина/высота каждого уровня,
  номера уровней и размер тайлов;
- `position`, `timestamp`, `defaultView` — положение, время и начальный вид;
- `tileUrlTemplate`, `localTileTemplate` — адреса тайлов и локальные пути;
- `rawResponse.data.Annotation` — переходы, граф соседей, подписи, организации
  и исторические панорамы; другие поля ответа тоже остаются в `rawResponse`;
- `capturedAt`, `sourceUrl`, `schemaVersion` — происхождение и версия формата.

`Origin` сохраняется без пересчёта: его соглашения нужно учитывать при реализации
просмотрщика, а не подменять предполагаемым `angularBBox`. Флаг
`geometryFieldsPresent` означает наличие основных полей, **не** проверку
корректности рендеринга. При изменении схемы ответ всё равно сохраняется,
а `missingFields` указывает отсутствующие основные поля.

Для реального примера `Z7lngTdIrFox` максимальный уровень имеет размер
18944 × 7271 при тайлах 256 × 256. Последнюю строку нельзя растягивать до
полных 256 пикселей или считать высотой панорамы 29 × 256. Для будущего
просмотрщика используйте оригинальные тайлы и размеры из манифеста.
`merge.py` создаёт плоскую картинку с подписью; для просмотра используйте архив тайлов.

### Обновление

1. Примените новую миграцию к существующей БД **от администратора PostgreSQL**
   или владельца схемы `aa` (V001 повторно запускать не нужно).
   У прикладного пользователя `allarchive` может не быть права `CREATE` в схеме:

   ```bash
   sudo -u postgres psql -d panoramas -v ON_ERROR_STOP=1 --single-transaction \
     < db/migrations/V002__Yandex_panorama_metadata.sql
   ```

2. Перезапустите Flask-сервер с обновлённым кодом. Модуль
   `monitoring-server/panorama_metadata.py` должен находиться рядом с сервером.
3. В Firefox откройте `about:debugging#/runtime/this-firefox` и перезагрузите
   расширение (или загрузите `pano-monitoring-yandex/manifest.json`). Добавлены
   разрешения на API метаданных, хранилище и таймер повторной отправки.
4. Перезагрузите страницу Яндекс Карт и откройте панораму. Уже прошедшие до
   загрузки расширения ответы задним числом получить нельзя.

Ответы отправляются на `POST /aa/yandex-panorama-metadata`. Сервер сохраняет
последний ответ для каждого `imageId` в `aa.yandex_panorama_metadata` (JSONB).
Повторная отправка того же ответа не создаёт дополнительную запись журнала;
более старый ответ не перезаписывает новый. Новый ответ также добавляет запись
в `panorama_log`, чтобы существующий загрузчик обнаружил изображение.
Координаты этой записи берутся из ответа, независимо от состояния вкладки.

Если сервер недоступен, расширение хранит последнюю полученную версию для
каждого изображения в `browser.storage.local` и повторяет отправку раз в минуту
и при запуске фонового скрипта. После подтверждения сервера запись удаляется
из очереди. Не удаляйте расширение/его данные до отправки очереди; для временного
расширения также не следует полагаться на сохранение данных при его удалении
Firefox. `unlimitedStorage` снимает обычную квоту очереди, но не ограничения диска.
Ошибка записи в хранилище отображается в консоли расширения.
Ответы больше 16 MiB пропускаются с сообщением в консоли, а не обрезаются.

Старый журнал запросов тайлов сохраняется. Теперь в его `panorama_log_meta`
есть также `observed_view.direction` и `observed_view.span` из URL. Это снимок
состояния интерфейса в момент запроса тайла, а не надёжная геометрия изображения
и не непрерывная запись положения камеры. Основной источник для просмотрщика —
таблица `yandex_panorama_metadata`.

### Проверка и экспорт без обращения к Яндексу

После открытия панорамы её манифест доступен через локальный сервер:

```bash
curl --fail http://127.0.0.1:5000/aa/yandex-panorama-metadata/Z7lngTdIrFox \
  -o map/Z7lngTdIrFox/metadata.json
```

Каталог для файла должен существовать. Экспорт содержит все исходные метаданные,
но не сами изображения. Соседние/исторические панорамы перечислены как ссылки;
их тайлы и полные метаданные не скачиваются автоматически. Для старых архивов
нужно повторно открыть соответствующие панорамы с обновлённым расширением.

### Тесты

Проверяются геометрия проекции, чтение тайлов, неполные архивы, CPU-рендер и CLI,
управление камерой, загрузка и отмена страниц атласа, работа с GPU через подмену
OpenGL, скачивание, склейка и обработка ошибок. Архитектурные тесты проверяют
shebang, размещение функций в классах, длину методов до 10 строк и зависимости.

```bash
node tests/metadata.test.js
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

Для отдельной проверки реального GTK/OpenGL нужны графическая сессия и локальный
архив. Команда проверяет управление, сохраняет снимок и закрывает окно:

```bash
.venv/bin/python viewer.py map/Z7lngTdIrFox --smoke-test /tmp/panorama-smoke.png
```

Код просмотрщика разделён на модель архива, чтение тайлов, геометрию проекции,
камеру, фоновую загрузку, OpenGL и GTK-интерфейс в `panorama_viewer`.
`panorama_archive` содержит загрузчик и склейку; сервер отделяет нормализацию
метаданных от SQL в `panorama_metadata.py` и `repository.py`. Корневые скрипты
сохраняют прежние точки входа.

Фикстура `tests/fixtures/yandex-panorama.json` — публичный ответ для точки
132.199871,43.357577, полученный 2026-09-23. Тесты проверяют сохранность данных,
передачу потока, сбой сервера, восстановление очереди и гонку ответов.
Firefox API и соединение PostgreSQL в этих тестах подменяются; запуск расширения
в настоящем Firefox и применение миграции проверяются отдельно.
