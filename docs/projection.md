# Проекция офлайн-просмотрщика

Проверено 2026-09-23 по публичному коду действующего плеера Яндекса:
[panorama-player-view/41b4d82ece190af025e4.yandex.ru.js](https://maps.yastatic.net/s3/front-maps-static/maps-front-maps/build/client/desktop/chunks/panorama-player-view/41b4d82ece190af025e4.yandex.ru.js).
Значимые функции: `parsePOVResponse`, конструктор `Panorama`,
`definePanoramaImageGrid`, `generateTileFrames`, `getCameraDirectionInPanorama`.
Сам код плеера в проект не включён; просмотрщик реализует преобразование самостоятельно.

## Значение Origin

`Data.EquirectangularProjection.Origin = [azimuth, horizonTilt]`, оба значения
в градусах. Первый задаёт азимут шва (нулевого столбца), второй — широту середины
панорамного изображения. Это не верхняя граница и не наклон всей сферической
системы координат, который нужно применять как поворот вокруг оси X.

Текущий плеер Яндекса вычисляет положение верхнего края по уровню с наименьшей
шириной `W_low` и его высотой `H_low`:

```text
colatitude_top = π/2 − π × H_low/W_low − radians(horizonTilt)
if colatitude_top < π/100:
    colatitude_top = 0
latitude_top = π/2 − colatitude_top
```

Порог π/100 соответствует 1,8°. Это воспроизводит привязку верхнего края к
зениту при округлённых размерах маленького уровня. Положение края едино для
всех уровней. Для выбранного уровня с точными размерами `W × H`:

```text
latitude_span = 2π × H/W
latitude_bottom = latitude_top − latitude_span
```

Пример `Z7lngTdIrFox`: `Origin = [-91.27, 20.908]`, маленький уровень 512 × 196,
большой — 18944 × 7271. Верхний край привязывается к +90°, нижний находится
примерно на −48,17°. Нижняя граница зависит от точного отношения H/W, а не от
количества целых тайлов. Непокрытая область не растягивается до южного полюса.

## Камера и выбор цвета

Система координат просмотрщика: X — восток, Y — вверх, Z — север.
Нулевой азимут смотрит на север, 90° — на восток. Наклон вверх положительный.
Для экранного пикселя строится луч перспективной камеры, повёрнутый в мировой
системе базисом `right, up, forward`:

```text
ray = normalize(forward + x × tan(vfov/2) × aspect × right
                        + y × tan(vfov/2) × up)
phi = atan2(ray.x, ray.z)
theta = asin(ray.y)
u = fract((phi − radians(Origin[0])) / 2π)
v = (latitude_top − theta) / latitude_span
```

Если `v` вне [0, 1], показывается тёмный фон. Иначе выбирается цвет развёртки
в координатах `(u × W − 0.5, v × H − 0.5)` с билинейной интерполяцией.
Горизонтальные координаты замыкаются, вертикальные при выборке крайних пикселей
ограничиваются границами изображения. GPU выбирает четыре пикселя вручную,
поэтому фильтрация работает и на границе текстурных страниц, и на шве 360°.

## Проверка

- Юнит-тесты покрывают углы, ортонормальность базиса камеры, шов, область ниже
  снятой панорамы, точное обрезание последней строки, неполные архивы и бюджет GPU.
- CPU-рендер читает исходные тайлы напрямую; GPU использует массив текстурных
  страниц. Их можно сравнить независимо при одинаковом размере кадра.
- Для `Z7lngTdIrFox`, азимута 60.583633°, наклона −7.411967° и вертикального
  обзора 60° изображение визуально сверено с открытой панорамой Яндекса.
- Различия в сглаживании, детализации, цветопередаче и наложенных подписях
  возможны: это самостоятельный плеер, а не пиксельная копия интерфейса Яндекса.
